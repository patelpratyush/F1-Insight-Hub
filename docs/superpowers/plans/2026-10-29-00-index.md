## Amendments to the spec (decided while planning)

These refine the spec and are mirrored into it.
1. A shared Python package `packages/db-py` (import name `f1_db`) holds SQLAlchemy models, the session factory, Alembic migrations and the object-storage client. Both `apps/api` and `apps/worker` depend on it. `packages/core-py` (import name `f1_core`) stays pure with no I/O.
2. The contract package generates TypeScript types and a fetch client with `openapi-typescript` and `openapi-fetch`. Zod is used on the web only for forms and env validation, not for response parsing.
3. Phase 0 adds a `driver_standings` table, because standings come straight from Jolpica and are not derived from results yet. It also adds an `ingestion_runs` table to power freshness labels and the lag alert.
4. Job queue decision: **Arq** (async-native, small, Redis-only). Recorded in ADR 0002.
5. Better Auth tables live in a separate Postgres schema named `auth`.
6. Live timing uses OpenF1 and is clearly labelled unofficial.

## Cross-phase conventions (every plan inherits these)

- **Commits:** Conventional Commits, one commit per task step group, never `--no-verify`.
- **Branching:** one branch per phase (`phase-N-name`), one PR per task group, merged only with all CI gates green.
- **TDD:** failing test first, minimal code, passing test, commit.
- **Names are contract.** If a later plan references a function, table or route, its exact name is defined in an earlier task. Do not rename without updating every plan.
- **Parity checklists:** each phase ends with a checklist against the legacy feature set. Nothing from `legacy` is copied.

## Execution handoff

After you review these plans, choose an execution method:
- **Subagent-driven:** fresh subagent per task with a review gate each time (most thorough).
- **Native:** I implement every task in-session, then one whole-branch review (fastest).
